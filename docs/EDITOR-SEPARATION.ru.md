# Koffice 0.18 — разделение офисных приложений, первый этап

**Цель:** вместо одной программы, в которой можно только переключать вкладки, начать создавать четыре самостоятельных продукта Kodi Office.

## Запуск

| Команда | Приложение |
| --- | --- |
| `koffice` | Общий Koffice Suite и лаунчер |
| `koffice --app writer` | Kodi Writer |
| `koffice --app sheets` | Kodi Sheets |
| `koffice --app slides` | Kodi Slides |
| `koffice --app base` | Kodi Base |

При запуске Koffice без параметров появляется панель выбора приложения. Каждая кнопка открывает **отдельный процесс операционной системы** с собственным заголовком окна, отдельным рабочим состоянием и выбранным редактором. Это не четыре вкладки одного окна.

Для самостоятельных приложений скрыта боковая навигация между редакторами; Ctrl+1..4 также не переключает их. Кнопка **Applications** запускает другие приложения в отдельных окнах. Общий режим Suite сохранён для привычной работы со всеми редакторами и функциями Fusion.

**Windows:** после компиляции можно запускать, например, `src-tauri\target\debug\koffice.exe --app writer` или `src-tauri\target\release\koffice.exe --app sheets`. Установленная версия принимает те же параметры, если указать путь к её исполняемому файлу.

Безопасность: запуск происходит через текущий исполняемый файл с одним из четырёх фиксированных аргументов. Пользовательский путь к произвольной программе не принимается.

## Чего пока нет

Это **первый этап**, а не четыре отдельных установочных пакета. Пока один общий EXE/исполняемый файл, который может работать в четырёх режимах, но каждый запуск идёт в собственном процессе. Дальше потребуются отдельные ярлыки, ассоциации форматов, обособленные установщики, более глубокая архитектура редакторов.

**Fusion между разными процессами пока не использует общую оперативную память.** Например, если Sheets открыт отдельным окном, Writer не видит его несохранённые изменения автоматически. Для такого взаимодействия нужен безопасный общий сервис документов/IPC. В интегрированном Suite прежние Fusion-сценарии сохранены.

Также остаются существенные ограничения самих редакторов: Writer ещё не стал полноценным постраничным текстовым процессором, Sheets требует масштабируемого интерфейса и десятков функций, Slides — расширенного холста и макетов, Base — конструктора форм и отчётов.

## Критерии этой итерации

- Четыре независимых процесса с отдельными окнами и состояниями.
- Единый лаунчер с выбором продукта.
- Прямой запуск продукта через аргумент CLI.
- Сохранение режима Suite и существующих функций Fusion.
- Строгая проверка аргументов запуска.
- Тесты на маршрутизацию интерфейса, команды Rust и кроссплатформенную сборку.

Следующие итерации должны быть **крупными редакторскими этапами**, а не добавлением одной декоративной кнопки. В приоритете Writer и Sheets, затем углубление Slides и Base.
